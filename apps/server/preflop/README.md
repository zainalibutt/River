# Offline heads-up preflop tables, version 1

For hand-dependent realisation and the new 100/200bb packs, see
[version 2](v2/README.md). This document and the v1 packs retain the flat-model comparison.

These are our own tables, generated by the dedicated TypeScript solver. Nothing here is
connected to a live bot policy. There is no commercial solver dependency.

## Game and tree

Heads-up NLHE, no rake/ante, button posts 0.5 bb, BB posts 1 bb. Effective stack includes
the blind and is a parameter, at least 1 bb. Seat 0 is button/in position after the flop.
All sizes below are **total contributions**, not additional chips.

| Decision | Actions |
| --- | --- |
| Button unopened | fold, limp to 1, open to 2.5, jam |
| BB after limp | check, raise to 4, jam |
| Button facing that raise | fold, call, jam |
| BB after open | fold, call, 3-bet to 9, jam |
| Button facing 3-bet | fold, call, 4-bet to 22, jam |
| BB facing 4-bet | fold, call, 5-bet jam |
| Any player facing a jam | fold, call |

There are 12 decision histories at 100 and 200 bb. Calling an ordinary raise or checking
a limp closes preflop betting. Every jam has its own call/fold response. A raise is at
least the previous full raise increment above the outstanding contribution; the initial
BB is a full 1 bb bet. Sizes are lifted to the legal minimum, capped by effective stack,
and identical targets are merged, with the capped action labelled jam. Short all-in
raises are allowed, but there is no further raise after either player is all-in.
At exactly 1 bb the BB is already all-in, so button can only fold/call.

## Continuation model

At a non-all-in leaf, for player p holding h:

```
rangeEquity(h) = sum_o compatibleDealWeight(h,o) * opponentReach(o) * equity(h,o)
                 / sum_o compatibleDealWeight(h,o) * opponentReach(o)
netUtility(h) = pot * rangeEquity(h) * realisation[p] - ownTotalContribution
```

The CFR traversal uses the unnormalised numerator and matching compatible reach mass,
which is algebraically the same formula. Opponent reach includes every opponent action
on the path. It is not the uniform starting range. The default factors are IP **1.05**,
OOP **0.95**, exposed as `--ip` and `--oop`. This is a simple documented model: a 5%
relative equity bonus for position and a 5% relative discount out of position. These are
explicit assumptions for later tuning, not empirical estimates or sourced solver outputs.

Shares are multiplied independently, without normalisation or clipping. Consequently
the continuation game is generally **not zero-sum**, and a holding's modelled share can
exceed the pot. Two utility functions are trained. No zero-sum convergence theorem is
claimed for this model; acceptance is by a measured independent best response.
For all-ins the factor is exactly 1: the same table's unadjusted showdown equity is used.
This is Monte Carlo equity, not exhaustive enumeration of every board.

Fold utility refunds the winner's uncalled chips: winner's net is the folder's total
contribution, folder's net is its negative. All utility is measured from the hand's start,
including the blinds. There are no side pots with equal effective stacks.

## Equity cache and symmetry

The ignored cache is `out/preflop-solve/equity-v1-8192.json`. It contains a 169 x 169
equity matrix and the exact number of compatible ordered physical deals in each cell.
The 169 classes cover all 1,326 two-card holdings; there are exactly 1,624,350 ordered
legal deals, or 1,225 possible opposing holdings for each physical hero combo.

For each distinct class pair, fix one representative hero combo and enumerate every
compatible opponent combo. Group only genuinely equivalent suit matchups by global
suit permutation and card order within a holding, retaining exact group multiplicities.
Sample 8,192 boards without replacement per matchup orbit using fixed seed 1369948382
(`0x51a7c0de`) mixed with the canonical matchup key. There are 46,683 sampled ordered
seat orbits, hence 382,427,136 sampled boards. Reverse cells are complements. Diagonal
class equity is exactly 0.5 by seat symmetry. Sample averages and class weights are kept
at full JavaScript number precision.

Every physical combo within a class is related by a global suit permutation. Against a
class-symmetric opponent policy, it has identical legal-opponent counts and identical
average equity. The 169-class solve is therefore a symmetry quotient, not an independent
rank-class/card-removal approximation. The exported `classCombos` expands it to all
1,326 combos. There are no per-combo policy differences. A separate BR enumerates
physical removal and permits a distinct response for each of the 1,326 holdings; its
values agree with the class BR to within 1e-8 bb. These class equities must not be used
later against arbitrary suit-asymmetric opponent ranges without further equity data.

The cache has a SHA-256 over version, ordering, multiplicities, exact deal counts,
equities, seed, sample count, orbit count and error metadata. Wall-clock generation time
is excluded from the hash. Wrong hashes, ordering, dimensions, seed/sample parameters,
complements or total deal mass are rejected. Fresh regeneration reproduces the hash:

```
088c145280ed4a7b7ad303a4838430abd17aaf9924536f45dafdad852763b8cb
```

Maximum estimated cell standard error is 0.005348 equity (0.535 percentage points).
The largest normal-approximate per-cell 95% radius is 0.010482 (1.048 percentage points).
A conservative simultaneous 95% Hoeffding/union-bound radius over all non-diagonal
cells is 0.028437 (2.844 percentage points). The latter uses squared orbit weights and
the usual independent-uniform Monte Carlo assumption for pseudorandom draws. Neither
number bounds continuation-model error. In particular the small solver exploitability
below does **not** imply equity-estimation error is below 0.01 bb at deep all-in leaves.

Class-weighted spot checks: AA/KK 0.819265, AKs/QQ 0.455261, 72o/AA 0.116079.
The allocation-free evaluator is checked against the engine on 5,000 fixed-seed random
seven-card hands and a targeted three-pair kicker case.

## Solver, independent certificate and files

Alternating full-deal vector DCFR uses alpha=1.5, beta=0, gamma=2; CFR+ is also available
through the trainer. Source: Brown and Sandholm,
[Solving Imperfect-Information Games via Discounted Regret Minimization](https://arxiv.org/abs/1809.04040).
Each player's regrets use compatible opponent counterfactual reach. Average strategies
use that player's own sequence reach and iteration weight t^2. No deal sampling occurs
during training. Strategies are evaluated after each block of 100 iterations.

The independent BR module has its own terminal arithmetic and traversal; it does not
read trainer kernels, regrets or stored trainer values. It chooses one action per own
information set, integrating hidden opponent holdings before maximising. It reports:

```
gain[p] = value(bestResponse[p], opponentAverage) - value(averageProfile, p)
NashConv = gain[0] + gain[1]
exploitability = NashConv / 2
percentOfPostedPot = 100 * exploitability / 1.5
```

Subtracting both profile values is necessary in the general-sum model. The certificate
is for the exported average policies, cached equity model and finite action tree only.
It does not certify full postflop poker, different action sizes, or estimation error.

`v1/100bb.json` and `v1/200bb.json` contain full tree, every decision's 169 strategy rows,
action meanings, compatible-reach-weighted aggregate frequencies, combo expansion,
continuation parameters, equity hash/error, iterations, measured runtime, all BR values,
gains, convergence checkpoints and certificate scope. `v1/*.txt` provides four 13x13
grids: button unopened, BB vs limp/open, button vs 3-bet. Cells show the leading action
and any additional action at least 10%, as letters and whole percentages. JSON retains
all small probabilities and is authoritative.

| Pack | Iterations | Solve plus BR seconds | Exploitability bb/hand | % of posted 1.5 bb pot |
| --- | ---: | ---: | ---: | ---: |
| 100 bb | 200 | 0.784 | 0.00090706 | 0.06047% |
| 200 bb | 800 | 2.251 | 0.00096951 | 0.06463% |

The accepted equity cache took 111.874 seconds to generate on this machine. Solve
timings above reuse that cache and exclude Node/tsx startup and JSON/grid writing.
All generator/solver runs are single-threaded. Results are deterministic apart from
wall-clock metadata. The CLI exits 2 if the target is not met, retaining an explicitly
uncertified pack for inspection; it never silently labels such a pack accepted.

## Bounded reproduction and checks (PowerShell, worktree root)

Set these variables before each command. Vitest uses one worker and no file parallelism;
the numerical solver itself uses one JS thread. No command needs a commercial solver,
network, live bot, git action, or output outside this worktree.

```powershell
$env:UV_THREADPOOL_SIZE='1'
$env:GOMAXPROCS='1'
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
$env:NODE_OPTIONS='--v8-pool-size=1'
cmd /c npx tsx apps/server/src/bot-preflop-solve-run.ts --depth 100 --target 0.001 --seconds 180
cmd /c npx tsx apps/server/src/bot-preflop-solve-run.ts --depth 200 --target 0.001 --seconds 180
cmd /c npx vitest run apps/server/src/bot-preflop-solve --maxWorkers=1 --no-file-parallelism
cmd /c npx tsc -p apps/server --noEmit
node apps/server/tools/check-preflop-mutations.mjs
```

The CLI defaults to 100 bb, 8,192 equity samples per orbit, 10,000 maximum iterations,
240 seconds total budget and target 0.0075 bb. `--seconds` is capped at 480 seconds,
including equity generation when missing; iteration blocks and final BR add a small
bounded overhead. Factors can be tuned with `--ip`/`--oop`, stack with `--depth`, and
sampling with `--samples`/`--seed`. Cache seed/sample mismatches fail explicitly. To
regenerate a cache, remove only that named ignored cache file or use another sample
count. Do not mix equity hashes when comparing packs.

The test suite checks an independently enumerated six-card, three-holding preflop toy
at 1.5 bb against all 216 BTN and 64 BB pure plans, solving it with both CFR+ and DCFR.
It also checks general-sum profile subtraction with an asymmetric reached range,
unreachable histories, missing/invalid policies, full/short-stack legality, duplicate
merging, all-in/fold payoffs, exact blockers, evaluator parity, equity spot checks and
exported pack integrity. When the ignored cache exists it independently re-certifies
both exported policies, recomputes reached frequencies and compares physical-combo BR.
Fresh checkouts still run all core/toy/equity tests without requiring the large cache.

The mutation runner first requires a passing baseline, then makes and restores eight
source mutations serially, requiring the intended named test to fail with exit code 1:

| Mutation | Witness |
| --- | --- |
| Subtract instead of add action value in regret update | toy solve fails exhaustive BR |
| Reverse sampled showdown winner | AA/KK, AKs/QQ, 72o/AA spot checks |
| Treat blocked holdings as compatible | exact combo/deal counts |
| Remove effective-stack cap | fractional/short-stack legality |
| Negate action values inside best-response maximum | independent exhaustive BR |
| Report NashConv/4 rather than /2 | exhaustive exploitability arithmetic |
| Use (BR0+BR1)/2 without profile subtraction | asymmetric general-sum witness |
| Apply realisation to preflop all-ins | exact no-factor all-in payoff |

Original source bytes are restored in `finally`. Logs and machine-readable summaries
stay under ignored `out/preflop-solve/mutations/`. The mutation process is bounded to
under eight minutes and each child test process to 45 seconds.
