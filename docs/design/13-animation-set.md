# 13 — Animation set

Resolves **Q10**, open since 2026-08-23: who authors River's seated animation clips.

## Q10 answered — procedural keyframing, no human animator

The question assumed two options: Zain hand-keys the clips, or a stock seated-animation pack is bought and adapted. Both were wrong, because **a seated poker character's entire motion range is a small number of bone rotations over time**, and bone rotations over time are exactly what a script can write.

Prototyped and verified on the MPFB rig at `D:/River-art/blend/char_animated.blend`:

| Clip | Length | Method | Verified |
|---|---|---|---|
| `IDLE_breathe` | 4.0s loop | Sine on spine and head, two frequencies so breathe and sway do not phase-lock | yes |
| `PEEK_card` | 1.2s one-shot | Head down, left forearm lifts the card corner, return | yes |
| `ALLIN_standup` | 1.8s one-shot | Legs extend, spine leans into the rise, head lifts | **yes — rendered as a frame strip, the rise reads clearly** |

The stand-up is the signature moment named in `docs/spec.md`, and it was the clip most likely to need real animation skill. It works.

**This removes the last hard dependency in the character pipeline.** No animator, no purchased pack, no per-clip manual labour. Clips are generated by the same deterministic scripts that build the meshes, which puts the whole set in DeepSeek's lane.

### What procedural authoring does not give you

Weight, anticipation, overlap, follow-through and per-archetype personality. The clips are correct and stiff. That is precisely the standard Zain set when he deferred polish: **the correct clip firing at the correct moment with correct timing.** A stiff clip that fires correctly passes; a beautiful clip that fires late does not.

A later polish pass can hand-refine any clip without changing the pipeline, because the generated action is an ordinary Blender action.

## The v1 set

Nine clips. Tiers are from the animation priority table in `07-motion.md` — lower tier interrupts higher.

| Clip | Length | Trigger | Tier | Author |
|---|---|---|---|---|
| `IDLE_breathe` | 4.0s loop | default state | 4 | procedural |
| `PEEK_card` | 1.2s | hole-card peek input held | **1** | procedural |
| `PRESET_reach` | 0.9s | preset action selected | **1** | procedural |
| `CHIP_toss` | 0.8s | bet, call or raise | 1 | procedural |
| `DEAL_toss` | 1.1s | rotating player-dealer venues | 1 | procedural |
| `ALLIN_standup` | 1.8s | all-in commit | 1 | procedural |
| `REACT_win` | 1.6s | pot award | 2 | procedural, pooled |
| `REACT_lose` | 1.4s | losing showdown | 2 | procedural, pooled |
| `FOLD_muck` | 0.7s | fold | 1 | procedural |

`PEEK_card` and `PRESET_reach` sit at tier 1 because they are **social tells**, not decoration. Other players read them. They are load-bearing gameplay and may not be dropped under fast pacing.

## Reaction pools

The behaviour reference notes the reference tripled its reaction count because repetition was visible. River generates variation rather than authoring it:

```ts
type ReactionIntensity = "subtle" | "normal" | "big"
type Outcome = "win" | "lose" | "split" | "knockout"
```

Each reaction clip is generated at three intensities by scaling rotation magnitudes and timing from one curve definition — three clips from one script for the cost of one. Selection inputs: all-in involved, pot as a share of the actor's stack, showdown reached, hand rarity, river changed the winner.

**Nine seats must not react identically.** Seed the intensity choice and the sub-frame timing offset per seat so a synchronised multi-way reaction still reads as several people rather than one puppet rig mirrored nine times.

## The all-in moment

Composed in `07-motion.md`; the animation half is:

| Beat | Timing | Layer |
|---|---|---|
| Chips push to the pot line | 0-320ms | table |
| Character begins to rise | starts 100ms | `ALLIN_standup` |
| Camera moves to the all-in framing | 0-600ms | camera director |
| Table light lifts 15% | 400ms up, 800ms down | lighting |
| `ALL IN` sets over the felt | 700ms | HUD |
| Character remains standing | through the run-out | pose hold |
| Reaction on the result | on award | `REACT_win` / `REACT_lose` |

Standing persists through the board run-out — the reference is explicit that all-in players stay standing into the result, and that multiple all-in players react in sync when cards reveal.

## Transitions

| Rule | Behaviour |
|---|---|
| Blend in and out | 120ms cross-fade between actions |
| Idle re-entry | Every one-shot returns to `IDLE_breathe` at a random loop phase, never frame 0 |
| Interrupt | A lower tier cuts a higher tier with a 80ms blend, never a hard pop |
| Emotes | Tier 3. Cancelled or accelerated the instant a tier 0-1 event fires |
| Fast pacing | Clip lengths unchanged; the **gaps** between them shorten. Never remove a clip |

**No animation may extend a turn timer.** The 15/20/20/25 budgets are independent of playback, and the poker state machine never waits for a clip to finish.

## Emotes

Separate from the reaction pool — player-triggered, throttled, disallowed during your own decision window by default.

Set, per Zain: wave, laugh, facepalm, fist-pump, throat-slit, chip trick, dance, confetti, table knock, plus voice quips written snide, quirky and sneaky in character.

| Complexity | Treatment |
|---|---|
| Simple gestures — wave, table knock, facepalm | procedural, animation only |
| Mid — fist-pump, throat-slit, chip trick | procedural with SFX |
| Complex — dance, confetti | procedural base, hand-polish candidate, plus SFX or voice |

Dance and confetti are the two where procedural authoring is weakest. They are also the two most droppable from v1 if they do not read.

## Acceptance criteria

- [ ] All nine clips generate deterministically from script, same output every run
- [ ] `ALLIN_standup` reads as a rise from seated to standing at the play camera
- [ ] `IDLE_breathe` loops without a visible seam and does not phase-lock across nine seats
- [ ] `PEEK_card` and `PRESET_reach` are visible to other seats and survive fast pacing
- [ ] Reaction clips generate at three intensities from one curve definition
- [ ] Nine seats reacting simultaneously read as nine people, not one rig mirrored
- [ ] Every one-shot returns to idle at a randomised loop phase
- [ ] No clip can extend or delay a turn timer
- [ ] Tier 0-1 events interrupt emotes within 80ms
- [ ] Clip set fits the character budget with no additional mesh cost
